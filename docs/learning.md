# 학습 노트

## 내 말 요약
공공데이터 CSV는 바로 쓸 수 있는 게 아니라 **먼저 열어 보고 확인해야 하는 재료**다.
이번 파일은 한글이 깨지는 CP949였고, 구(區) 열이 없었고, 내가 궁금했던 '국립'이라는 값도 없었다.
그래서 PRD를 데이터에 맞춰 고쳤고(국립/공립 구분 삭제), 앱은 "구와 유형을 고르면 목록이 나온다"는 하나의 시나리오만 끝까지 동작하게 만들었다.
숫자(491, 91, 24, 170, 5)를 CSV에서 먼저 세어 두고, 화면에서 같은 숫자가 나오는지 눌러서 확인하는 방식으로 점검했다.

## 1. 인코딩 (CP949 → UTF-8)
- 공공데이터포털 CSV는 CP949(EUC-KR)인 경우가 많다. UTF-8로 읽으면 `����`처럼 깨진다.
- Node에서는 따로 패키지 없이 `new TextDecoder('euc-kr').decode(buffer)`로 읽을 수 있다 (`scripts/build-data.mjs`).

## 2. CSV는 쉼표로만 자르면 안 된다
- 주소에 `"…(팔용동, 원풍벽산아파트)"`처럼 따옴표 안 쉼표가 있다. `split(',')`을 쓰면 열이 밀린다.
- 따옴표 안인지 밖인지 기억하며 한 글자씩 읽는 파서를 썼다.

## 3. 없는 열은 다른 열에서 뽑는다 (정규식)
- 구 열이 없어서 주소에서 `(의창|성산|진해|마산합포|마산회원)구`로 뽑았다.
- 띄어쓰기로 자르면 `창원시마산합포구`처럼 붙어 있는 27곳에서 실패한다. 구 이름 목록으로 찾으면 491곳 모두 뽑힌다.
- 뽑기에 실패하면 스크립트를 멈추게 해서, 틀린 데이터가 조용히 들어가는 것을 막았다.

## 4. 이름보다 분류 열을 믿는다
- `국립창원대학교 직장어린이집`은 이름에 '국립'이 있지만 유형은 `직장`이다.
- 이름으로 추측하지 않고, 데이터가 정한 `어린이집유형구분` 열을 그대로 보여 준다.

## 5. 서버 함수(Vercel `api/`)와 정적 파일(`public/`)
- `public/` 안의 파일은 그대로 웹페이지가 되고, `api/daycares.js`는 `/api/daycares` 주소로 실행되는 서버 함수가 된다.
- 화면은 `fetch('/api/daycares?gu=성산구&type=국공립')`로 필요한 것만 받는다.
- 허용 목록(`api/_lib/constants.js`) 밖의 값이 오면 400을 돌려준다 → 이상한 입력을 서버에서 막는다.

## 6. 왜 Supabase 대신 JSON으로 먼저 만들었나
- Supabase 커넥터가 연결되지 않아 키를 받을 수 없었다.
- 데이터가 2026-09-03 하루치로 고정이라, 491행 JSON 파일 하나로도 핵심 시나리오가 충분히 동작한다.
- 키가 필요 없으니 **저장소에 비밀 값이 들어갈 일도 없다.** Supabase는 다음 할 일로 옮겼다.

## 7. 보안 습관
- `.env`는 `.gitignore`에 넣고, 저장소에는 값이 빈 `.env.example`만 올린다.
- 커밋 전에 키처럼 생긴 문자열(`eyJ…`, `sk-…` 등)이 없는지 검색한다.
