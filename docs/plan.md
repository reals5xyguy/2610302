# 첫 버전 계획 — 창원시 어린이집 찾기

## Context
`my-project/PRD.md`(v2)의 핵심 시나리오를 처음부터 끝까지 동작하게 만드는 첫 버전 계획이다.
핵심 시나리오: 보호자가 **구**와 **유형**을 고르면 어린이집 목록(이름·주소·정원·교직원 수)과 "2026-09-03 기준"이 보인다.
현재 폴더에는 `index.html`(할 일 목록), `PRD.md`, `data/…20260903.csv`(CP949, 491행)만 있다. 확인된 개발 환경은 Node v24.20.0, npm 11.19.0, Vercel CLI 65.8.0이다.
상태: 2026-10-30 계획 승인. **코드는 아직 만들지 않았다.**

## 2. 데이터 흐름

```
CSV(CP949) ──[1회 실행: scripts/import.mjs]──▶ Supabase 테이블 daycares
                                                     │ (읽기 전용 RLS 정책)
화면 index.html ──fetch /api/daycares?gu=&type=──▶ api/daycares.js ──▶ Supabase
```

### 결정: 공공데이터를 Supabase에 넣는다 (API를 바로 부르지 않는다)
- **바로 부를 API가 확인되지 않았다.** PRD에서 출처 URL은 "확인 필요"이고, 손에 있는 것은 CSV 파일 하나다.
- **한 번만 손질하면 되는 데이터다.** 기준일이 2026-09-03 하나뿐이다. CP949 변환, 주소에서 구 추출, 키(이름+주소) 생성을 매 요청마다 하지 않고 넣을 때 한 번만 한다.
- **필터를 DB가 처리한다.** `gu`, `type` 열에 조건을 걸어 필요한 행만 받는다.
- 원본 API를 확보하면 import 스크립트만 바꾸면 된다. 화면과 api/는 그대로 둔다.

### Supabase 테이블 `daycares`
| 열 | 타입 | CSV 원본 |
|---|---|---|
| id | bigint identity PK | — |
| name | text | 어린이집명 |
| dong | text | 행정동명 |
| type | text | 어린이집유형구분 |
| capacity | int | 정원수 |
| staff | int | 보육교직원수 |
| address | text | 소재지도로명주소 |
| gu | text | 주소에서 정규식 `(의창\|성산\|진해\|마산합포\|마산회원)구`로 추출 |
| basis_date | date | 데이터기준일자 |

- `unique(name, address)` 제약을 둔다 (PRD 한계: 같은 이름 7쌍).
- `gu`, `type`에 인덱스를 둔다.
- RLS를 켜고 `select`만 허용하는 정책 1개를 둔다.

### `scripts/import.mjs` (1회 실행)
1. CSV를 `iconv-lite`로 CP949에서 UTF-8로 디코딩하고, `csv-parse`로 파싱한다. 따옴표 안의 쉼표도 처리된다.
2. 행마다 `gu`를 추출한다. **추출에 실패한 행이 있거나 전체가 491행이 아니면 중단한다.**
3. `name,address` 기준으로 upsert한다. 다시 실행해도 행이 중복되지 않는다.
4. 마지막에 유형별·구별 개수를 출력해 PRD 3.1 표와 비교한다.

### `api/daycares.js` (Vercel 서버 함수, GET)
- 입력: `gu`, `type` (선택). 허용 목록 밖의 값이 오면 400을 돌려준다.
- Supabase에서 name, address, capacity, staff, type, gu를 select하고, 조건을 걸고, 이름순으로 정렬한다.
- 출력: `{ basisDate, count, items: [...] }`
- 키는 서버 환경변수(`SUPABASE_URL`, `SUPABASE_ANON_KEY`)에만 두고 브라우저에 노출하지 않는다.

## 3. AI 기능
- **핵심 시나리오에는 AI가 필요 없다.** 구·유형 필터와 목록 표시만으로 끝난다. 그래서 첫 버전에는 OpenRouter를 넣지 않는다.
- 나중에 넣는다면: "성산구 국공립 중 정원 큰 곳은?" 같은 질문을 받아 `api/ask.js`가 먼저 Supabase에서 조건에 맞는 행을 가져온다. 그 행만 OpenRouter에 근거로 넘기고, 시스템 프롬프트로 "주어진 행에 없는 내용은 '데이터에 없음'이라고 답하라"고 제한한다. 이 내용은 아래 "나중에" 목록에 둔다.

## 5. 사전 조건 (막히는 지점)
- **Supabase 프로젝트와 키가 필요하다.** 현재 Supabase 커넥터는 인증되지 않은 상태다. 사용자가 로그인하거나 프로젝트 URL과 키를 `.env`에 넣어야 import를 할 수 있다.
- 배포 위치(Vercel 계정)는 확인 필요. 첫 버전은 로컬 `vercel dev`로 확인한다.

## ⭐ 처음 볼 가능성이 큰 기술: Supabase RLS (Row Level Security)
테이블의 **행마다 누가 읽고 쓸 수 있는지를 DB가 직접 검사**하는 기능이다. RLS를 켜고 정책이 하나도 없으면 아무도 읽을 수 없다. 그래서 "누구나 select만 가능" 정책을 꼭 넣어야 한다. 이 정책 덕분에 anon 키가 새어 나가도 데이터를 고치거나 지울 수 없다. 첫 버전에서 "목록이 비어 있음" 문제가 생기면 가장 먼저 의심할 곳이다.
